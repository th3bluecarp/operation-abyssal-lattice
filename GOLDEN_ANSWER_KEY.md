# Operation Abyssal Lattice — Golden Answer Key

## Executive finding

Halcyon Meridian suffered one coordinated intrusion with two initially separate tracks that converge at Box. Track A compromised executive assistant `e.park@halcyonmeridian.com` through an adversary-in-the-middle board-portal lure, reused the captured authenticated session from `45.83.64.19`, established OAuth persistence through the unverified `Docs Sync Service`, and accessed confidential board and Meridian diligence material. Track B compromised developer `r.kapoor` through malicious `build-linker@1.1.7` package lifecycle code on `MAC-DEV-17`, accessed a GitHub credential, established LaunchAgent persistence, modified the unprotected `hotfix/cache-key` reusable-workflow ref, used GitHub Actions OIDC to assume `gha-release-role`, created `partner-export-sync` in the `prod` Kubernetes namespace, obtained the production Box token through the workload role, built `regulated_delta.7z`, and published it through an open Box link.

The decisive cross-track correlation is Box's 2026-03-13 17:36:02Z download of `regulated_delta.7z` from `45.83.64.19`: the same external IP responsible for the session reuse, OAuth grant, M365 access, and Google Drive activity. This supports coordinated control of both tracks without supporting attribution to a named actor, group, or country.

## Scope, impact, and uncertainty

Confirmed affected assets are `e.park`, `r.kapoor`, `FIN-WS22`, `MAC-DEV-17`, `actions-infra`, the mutable hotfix ref, release-orchestrator run 8841, `gha-release-role`, the `prod` export workload, `/prod/export/box_token`, the named board/M&A objects, `customer_delta.parquet`, `partner_map.csv`, and `regulated_delta.7z`. `a.velasquez` is targeted only. `t.owens` approved the run but is not shown compromised.

The `gha-release-role` policy exposes `/prod/*`, and the SSM inventory includes release-signing endpoint/token names. The bounded 17:00–19:00 KMS export contains Decrypt/GenerateDataKey but no `Sign`; no supplied workflow, audit, or service record demonstrates signing. Therefore signing credentials are conditionally exposed, while signing misuse is unproven. The exact rows within the archive, additional activity hidden by the S3 selector change, and whether further developer credentials were accessed remain unresolved.

## Required response priorities

Immediately revoke `e.park` sessions and OAuth grants; remove `Docs Sync Service`; investigate and protect `a.velasquez`; isolate and rebuild `FIN-WS22`, `MAC-DEV-17`, and separately `RSCH-JUP-03`; remove the LaunchAgent and malicious dependency; revoke GitHub/deploy credentials; delete and protect the hotfix ref; disable run/workflow artifacts; invalidate OIDC/cloud sessions; rotate the Box token and every `/prod/*` secret reachable by `gha-release-role`; remove open Box links; preserve the exfiltrated archive and audit evidence; and scope access across the data-event gap. Follow with immutable workflow SHA pinning, comprehensive branch rules, package provenance and lifecycle controls, least-privilege OIDC trust/policies, OAuth-consent governance, complete CloudTrail data-event retention, and legal/privacy review for board, M&A, partner, and regulated-data exposure.

## Prohibited conclusions

Do not claim all alerts are one intrusion, password theft, `a.velasquez` compromise, `t.owens` complicity, release-signing use, ransomware/destruction, tenant-wide access, anti-forensic ownership of the selector change, or named threat-actor attribution. Absence in incomplete telemetry is not evidence of absence.
